# 03 · 实现：一步步做白名单签名

> 目标：用一张**序列号与目标车机系统证书一致**的自签证书，给自己的 APK 签名，
> 让它通过安装门。
>
> 本仓库不提供任何真实序列号或私钥。下面的 `<TARGET_SERIAL>`、`<TARGET_DN>` 都需要你
> 从自己的车机上提取。

---

## 0. 前置工具

| 工具 | 用途 | 来源 |
|---|---|---|
| JDK（8~17） | `keytool`、`apksigner` 运行时 | Adoptium / Oracle |
| Android SDK Build-Tools | `zipalign`、`apksigner` | SDK Manager |
| OpenSSL | 生成指定序列号的证书 | Git Bash 自带 / 独立安装 |
| adb | 安装与验证 | platform-tools |

检查：

```bash
java -version
keytool -help | head -3
openssl version
apksigner --version
adb version
```

> Windows 上 `apksigner` 是 `apksigner.bat`，建议把 build-tools 目录加入 PATH，
> 或像示例脚本一样用变量指向。

---

## 1. 提取目标序列号

### 1.1 从官方 APK 提取

从你车机的应用商店下载任意一个**能正常安装**的官方 APK，然后：

```bash
keytool -printcert -jarfile official.apk
```

输出里找：

```
Owner: CN=..., OU=..., O=..., ...
Issuer: ...
Serial number: <TARGET_SERIAL>
Valid from: ...
```

或者用 apksigner（信息更直观）：

```bash
apksigner verify --print-certs official.apk
```

输出：

```
Signer #1 certificate DN: <TARGET_DN>
Signer #1 certificate serial number: <TARGET_SERIAL>
```

记下：

- `<TARGET_SERIAL>`：十六进制序列号（不带 `0x` 或带都行，下一步会统一）；
- `<TARGET_DN>`：DN 字符串，建议照抄，虽然不校验，但保持一致更稳。

### 1.2 注意

- **不同车型/平台序列号不同**，网上教程里的值不能照抄；
- 同一个平台的不同 OTA 版本也可能变，升级后要重新提取；
- 不要从别人给的 APK 里提取——你无法确认那是不是改过的。

---

## 2. 生成 RSA 密钥

```bash
openssl genrsa -out private.key 2048
```

说明：

- 用全新的密钥，不需要厂商私钥；
- `private.key` 是你的签名身份，**不要提交、不要外发**；
- 权限建议 `chmod 600 private.key`。

---

## 3. 生成自签证书（关键一步）

`keytool -genkeypair` **不能指定序列号**（它随机生成），所以必须用 OpenSSL：

```bash
# 1) 生成 CSR，DN 填从官方 APK 抄来的值
openssl req -new -key private.key -out csr.csr \
  -subj "<TARGET_DN>"

# 2) 自签证书，用 -set_serial 指定目标序列号
openssl x509 -req -in csr.csr -signkey private.key \
  -out certificate.crt -days 3650 \
  -set_serial 0x<TARGET_SERIAL>
```

参数说明：

| 参数 | 说明 |
|---|---|
| `-days 3650` | 有效期 10 年；车机不校验有效期，但签名工具会 |
| `-set_serial 0x...` | 必须是十六进制，加 `0x` 前缀 |
| `-subj` | DN 字符串，格式如 `/C=CN/ST=.../L=.../O=.../OU=.../CN=...` |

### 3.1 序列号格式

`keytool` 输出可能是：

- 十六进制：`a1b2c3d4e5f60718`
- 带前导零：`0a1b2c3d...`

OpenSSL 的 `-set_serial` 接受 `0x` 开头的十六进制。如果你的值是十进制或带空格，
先转换干净：

```bash
# 去掉空格和冒号，确保是十六进制
SERIAL=$(echo "<TARGET_SERIAL>" | tr -d ' :' | tr 'A-F' 'a-f')
openssl x509 -req -in csr.csr -signkey private.key \
  -out certificate.crt -days 3650 -set_serial "0x${SERIAL}"
```

### 3.2 验证证书

```bash
keytool -printcert -file certificate.crt
```

确认：

- `Serial number` 与目标一致；
- `Owner` 是你填的 DN。

---

## 4. 打包成 PKCS12

`apksigner` 需要 keystore，把证书和私钥打包：

```bash
openssl pkcs12 -export \
  -in certificate.crt -inkey private.key \
  -out my-car.p12 -name cert
```

执行时会提示设置**导出密码**，这就是签名时要输的口令。

> 建议用环境变量传入，不要写进脚本：
>
> ```bash
> export KS_PASS='your-password'
> ```

---

## 5. 对齐

签名之前必须对齐，顺序不能反：

```bash
zipalign -f 4 input-unsigned.apk aligned.apk
```

---

## 6. 签名

```bash
apksigner sign \
  --ks my-car.p12 \
  --ks-key-alias cert \
  --v1-signing-enabled true \
  --v2-signing-enabled true \
  --v3-signing-enabled true \
  --out output-signed.apk \
  aligned.apk
```

不传 `--ks-pass` 时，apksigner 会交互式提示输入口令，密码不落脚本。

要点：

- **v1 + v2 + v3 都开**：车机多为旧版 Android，只签 v2/v3 可能报"解析包错误"；
- 先对齐再签名；签名后再 zipalign 会破坏 v2/v3；
- 如果 apksigner 报证书有效期问题，把 `-days` 调大。

---

## 7. 验证

```bash
apksigner verify --print-certs output-signed.apk
```

确认：

```
Signer #1 certificate DN: <TARGET_DN>
Signer #1 certificate serial number: <TARGET_SERIAL>
Verified: true
```

**看 serial number，不是看指纹**。序列号对了，安装门才会放行。

---

## 8. 安装

```bash
adb install -r output-signed.apk
```

如果失败，对照第 10 节的错误表。

---

## 9. 完整脚本

本仓库的 `examples/` 提供了三个可复用脚本：

```bash
# 查看证书（官方包 / 自己的包都行）
bash examples/check_cert.sh official.apk

# 按目标序列号生成证书（交互输入 DN 和口令）
bash examples/gen_whitelist_cert.sh <TARGET_SERIAL> "<TARGET_DN>"

# 对齐 + 签名 + 验证
bash examples/sign_apk.sh input-unsigned.apk output-signed.apk
```

脚本不含任何真实值，全部通过参数或环境变量传入。

## 10. 常见错误

| 报错 | 原因 | 处理 |
|---|---|---|
| `INSTALL_FAILED_VERIFICATION_FAILURE` | 序列号不匹配 | 重新提取目标序列号，检查 `-set_serial` |
| `INSTALL_FAILED_INVALID_APK` | 未对齐 / 签名损坏 | 按"对齐 → 签名"顺序重做 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 已装版本的签名不同 | 先卸载旧版（会丢数据），或改包名 |
| `Signer #1 certificate serial number` 不对 | `-set_serial` 格式错（十进制/前导零） | 转成 `0x` 十六进制 |
| `apksigner` 报证书过期 | `-days` 太小 | 重新生成，`-days 3650` 或更大 |
| 装上了但卸不掉 | 卸载门（包名白名单） | 这是预期行为，见 [02-原理](02-原理-两道门的校验逻辑.md) |

---

## 11. 安全边界

- 这张证书只能让你的应用**通过安装门**，不等于获得系统权限；
- 它不会让应用自动进入包名白名单，也不会让进程名进入 CarService 白名单；
- 签对序列号后，应用会被系统视为"授权应用"，**反而更难卸载**；
- 不要用这套方法给来源不明的 APK 签名——你等于在为它背书。
