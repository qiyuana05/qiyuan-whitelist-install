# 05 · 风险与恢复

> 签名本身不会损坏车机，但"装上了卸不掉"是最常见的翻车场景。动手前先想好退路。

---

## 1. 风险分级

| 操作 | 风险 | 后果 | 可恢复性 |
|---|---|---|---|
| 查看证书序列号 | 🟢 低 | 无 | — |
| 生成自签证书 | 🟢 低 | 无 | — |
| 用目标序列号签名自己的 APK | 🟠 中 | 能装，但可能卸不掉 | 取决于包名 |
| 覆盖安装已存在的应用 | 🟠 中 | 签名冲突，安装失败 | 需先卸载 |
| 给来源不明的 APK 签名 | 🔴 高 | 等于为它背书，可能带来安全风险 | **不要做** |
| 修改系统分区 / 替换 Settings 证书 | 🔴 极高 | 系统完整性破坏、OTA 失败 | 恢复出厂/刷机 |

---

## 2. 装不上怎么办

按报错逐项排查：

| 报错 | 检查 |
|---|---|
| `INSTALL_FAILED_VERIFICATION_FAILURE` | `apksigner verify --print-certs` 看序列号是否等于目标 |
| `INSTALL_FAILED_INVALID_APK` | 是否先 zipalign 再签名；v1 是否开启 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 是否已有同包名不同签名的版本 |
| `INSTALL_FAILED_OLDER_SDK` | `AndroidManifest.xml` 的 `minSdkVersion` |
| `INSTALL_PARSE_FAILED_MANIFEST_MALFORMED` | manifest 语法/包名格式 |

### 2.1 序列号不对

```bash
# 重新提取
keytool -printcert -jarfile official.apk | grep -i serial
# 重新生成证书
openssl x509 -req -in csr.csr -signkey private.key \
  -out certificate.crt -days 3650 -set_serial 0x<TARGET_SERIAL>
```

注意 `-set_serial` 的值必须是十六进制，且不要带空格或冒号。

## 3. 卸不掉怎么办

这是最常见的问题。先确认原因：

```bash
adb shell pm list packages | grep <pkg>
adb shell dumpsys package <pkg> | grep -i signed
```

### 3.1 先尝试冻结（保留数据）

```bash
adb shell pm disable-user --user 0 <pkg>
```

效果：应用被禁用，不再运行，但数据保留，可随时恢复：

```bash
adb shell pm enable <pkg>
```

这是最安全的软方案，推荐优先使用。

### 3.2 换一个可卸载的包名

如果你的应用还没定型：

- 从自己车机的白名单里选一个**未被占用**的包名；
- 改包名、重新签名、重新安装；
- 旧包用 `disable-user` 冻结。

注意：改包名不会让应用自动进入白名单，只是换一个候选。

### 3.3 用 root 删除（高风险）

如果车机有 root 通道：

```bash
# 仅示意，不保证适用；先备份
adb shell su -c "pm path <pkg>"
```

直接删除 APK 文件可能破坏系统完整性校验，导致 OTA 失败。**不建议**在没有恢复方案时操作。

### 3.4 恢复出厂

最后手段。会清除所有用户数据与应用，但通常能恢复系统默认状态。

### 3.5 定向 hook（不提供代码）

社区中有通过 Frida hook `checkWhiteList` 绕过卸载校验的做法。本仓库**不提供**这类代码：

- 它需要 root + Frida，风险高于签名本身；
- 不同 OTA 版本 hook 点会变；
- 一旦 hook 失败，可能留下半删除状态。

如果你确实需要，请自行评估并准备好恢复方案。

## 4. 覆盖安装失败

`INSTALL_FAILED_UPDATE_INCOMPATIBLE` 的原因：

- 设备上已有同包名应用；
- 新 APK 的签名与旧版不同。

处理：

1. 备份应用数据（如果支持 `adb backup` 或应用自带导出）；
2. 卸载旧版（未签名匹配时可能卸不掉，先 `disable-user`）；
3. 安装新版；
4. 恢复数据。

**不要**为了覆盖而反复换证书——每次换证书都会让版本更难管理。

---

## 5. 保修、安全与法律

- 伪造序列号签名会绕过厂商的安装校验，可能被视为非授权修改；
- 签对序列号的应用会被系统当成"授权应用"保护，卸载更困难；
- 可能影响 OTA、保修与诊断；
- 不要把本方法用于他人车辆，也不要为来源不明的 APK 签名；
- 不同地区对车辆改装/诊断有不同法律要求，请自行确认。

---

## 6. 不要做的事

- ❌ 不要给来源不明的 APK 签名后安装；
- ❌ 不要修改 `/system`、替换 Settings 证书或删除系统应用；
- ❌ 不要把真实序列号、私钥、keystore 提交到公开仓库；
- ❌ 不要把"白名单签名"包装成收费服务；
- ❌ 不要在 OTA 期间做签名/覆盖安装。

---

## 7. 出问题怎么求助

在 Issue 中提供：

- 车型 / 年款 / OTA 版本；
- 你执行到哪一步；
- `adb install` 的完整报错（不要贴序列号、VIN、包名中的个人信息）；
- `apksigner verify --print-certs` 的输出（**把序列号打码**）。

不要上传完整 APK、keystore、whitelist.json 或原始日志。
